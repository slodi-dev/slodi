# PlanGrid: side columns and the fundur element

The Rist's **ATH** and **Innkaup** columns came over from the spreadsheet the sveit used to plan
in, and they didn't connect to the rest of Vinnubekkurinn. The first round tried four directions
(A · Two columns, B · Reminders and kit, C · One Vikan cell, D · Week panel).

**Picked: A · Two columns** (2026-10-19). B, C and D have been removed.

**New: A5 · Stimplar (as the calendar).** The Dagatal picked and polished D4 · Stimplar, and A5
brings that same stamp language to the grid. It comes first in the Comparison, and "Grid next to
calendar" shows the two views one above the other.

The second round keeps A's side columns and works on the other complaint: the fundur element in
each cell is a generic card that the eye glazes over. Variations A1–A4 each give the element its
own language. Each one also adjusts the side columns to suit it.

## Why A

- It keeps the grid's own shape: two columns, the same overline type, nothing to open.
- The **Endurmat** column answers "what did last time teach us about this week's liðir?". Each
  note links to its liður on the bench.
- The **Búnaður** column answers "what do we still have to find?". It's a checklist gathered
  from the week's liðir, with vantar on top and owned items folded away.
- B's reminders and C/D's extra click were more machinery than the leader asked for.

## Data note

### What exists today

| Data           | Where                                    | What it is                                                                                                                                                     |
| -------------- | ---------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Week note      | `PlanWeek.note` (grid contract)          | The ATH column today. One line of free text per week, with no author, due date or link.                                                                        |
| Fundur needs   | `PlanEntryBase.needs: string[]`          | Innkaup today. PlanGrid unions the strings per week and de-duplicates only exact matches. No quantity, no liður, no owned/needed state.                        |
| Liður endurmat | `Lidur.endurmat: string \| null` (bench) | One string carried from last time. LidurRow shows only the marker "Endurmat frá síðast" (the text is a tooltip). No tone, author, date or source run.          |
| `EndurmatNote` | SPEC §2 C, sc-155                        | Specced (corrective, positive, several collapsed) but **not built**. The tone split here follows it.                                                           |
| Bank equipment | Backend `Content.equipment: list[str]`   | **Real, on the backend.** Free strings on bank programs, events and tasks, filterable. Not copied to a liður when a block is added to a fundur. No quantities. |
| Fundur status  | `PlanStatus` on every entry              | staðfest, drög, óvíst, óákveðið ("?"). All four elements below lead with it.                                                                                   |
| Liðir count    | `item_count`                             | A total only. How many of them are decided isn't on the grid.                                                                                                  |

None of the plan endpoints exist on the backend yet; the frontend types are the contract the
backend will implement. Everything below proposes additions to that contract.

### What is missing, and the proposed shapes

**Búnaður, sc-644.** A sveit-wide catalogue, a list of needs on each liður, and the owned/needed
state per sveit and week.

```ts
type GearItem = {
  id: string;
  workspace_id: string;
  name: string; // "Vasaljós"
  consumable: boolean; // eldsneyti, eldspýtur: quantities add up instead of being shared
  unit?: { one: string; many: string } | null; // { one: "brúsi", many: "brúsar" }
};
// Lidur.gear?: { item_id: string; qty: number }[]
// When a bank block is added to a fundur, its Content.equipment strings are matched to
// catalogue items by name (or new items are created) and copied onto the liður.

type WeekGearState = {
  season_id: string;
  week_index: number;
  item_id: string;
  state: "eigum" | "vantar"; // no row means "óvíst"
  updated_by: string;
  updated_at: string;
};
// GET /seasons/{id}/weeks/{n}/gear →
//   { items: { item: GearItem; qty: number; state: "eigum" | "vantar" | "ovist";
//              sources: { lidur_id; lidur_name; event_id; event_title; qty }[] }[] }
// PUT /seasons/{id}/weeks/{n}/gear/{item_id}   { state: "eigum" | "vantar" | null }
```

Two rules to agree on. Reusable kit takes the largest quantity any one liður needs (the same
twelve vasaljós serve Tuesday's and Thursday's fundur); consumables add up. And a **cancelled**
fundur's liðir drop out of the list. The state belongs to the sveit, not to each flokkur.

**Endurmat, sc-645.** Endurmat that knows where it came from: which block the liður was reused
from, so the server can find the latest run of that block that has a note.

```ts
type Endurmat = {
  id: string;
  lidur_id: string; // the run it was written after
  text: string;
  tone: "positive" | "corrective" | null;
  written_by: { id: string; name: string };
  written_on: string;
};
// Lidur.source_block_id?: string
// Lidur.endurmat_from_last?: Endurmat | null   (replaces the bare string)
// GET /seasons/{id}/weeks/{n}/endurmat →
//   { endurmat: Endurmat; lidur_id; lidur_name; event_id; event_title; patrol_id | null }[]
// PlanEntryBase.has_endurmat?: boolean   (the small speech-bubble on the fundur element)
```

**Reminders, sc-643.** A doesn't show reminders, so they aren't in this lab any more. The
proposed shape stands for later: a `WeekReminder { id, season_id, week_index, text, due_on,
done_at, created_by, created_at }` with CRUD under `/seasons/{id}/weeks/{n}/reminders`. It
would replace `PlanWeek.note`.

**The fundur element.** What the cells need to say something at a glance:

```ts
// On PlanEntryBase:
ends_at?: string | null; // a fös–sun útilega; today there is only starts_at
cancelled?: { reason: string } | null; // or a PlanStatus "cancelled"
decided_count?: number | null; // liðir decided, next to item_count
// On PlanCell:
patrol_ids?: string[]; // a joint event of several flokkar (the lab's span_patrols)
// On Patrol (optional; the lab derives it):
usual_slot?: { weekday: 0 | 1 | 2 | 3 | 4 | 5 | 6; time: "HH:MM" } | null;
```

The lab **derives** each flokkur's usual evening from its own fundir (the most common weekday
and time). From that it finds a moved fundur, so `usual_slot` is only needed for a flokkur with
too few fundir to tell.

## Routine and exceptions

Most weeks, every flokkur has its ordinary fundur on its ordinary evening. That shouldn't need
reading, so:

- **The usual evening moves to the column header** ("Refir · þri. 19:30"). A routine element
  shows no time at all.
- **An exception says so in words, with an icon**, in every variation:
  - "Færður · fim. 19:30" for a moved fundur;
  - "fös.–sun." with a tent for an útilega;
  - "lau. 10:00" with a mountain for a dagsferð;
  - "Fellur niður", with the title struck through, for a cancelled fundur.
- **Spans show reach.** A joint útilega of Refir and Ernir spans their two columns
  (`span_patrols`). A troop-wide útilega spans the row. A two-week badge spans two rows.
- Every element is a button whose **accessible name is the whole story**, exceptions and
  readiness included. For example: _"Uglur: Ratleikur um hverfið, 5. nóv. kl. 19:30, fellur
  niður: Skólaferðalag"_, or _"Refir og Ernir: Útilega í Heiðmörk, 23. okt. til 25. okt.,
  staðfest, ákveðnir liðir 5 af 5, endurmat frá síðast"_.
- **Links between the columns:** a fundur whose liðir carry endurmat shows a small speech bubble,
  and each note in the Endurmat column starts with the flokkur's initial chip.

## The variations

### A5 · Stimplar (as the calendar)

**The story it tells:** "The Rist and the Dagatal are the same stamp book, seen by week and by
day."

**How it matches the calendar.** It's built from the real calendar's code, imported rather
than copied:

- The fundir are the same: the calendar's `calendarGrid()` fixture and `placeEntries()`, so the
  same October appears in both.
- Each flokkur's cell holds the calendar's exported `StampEntry`. That gives it the kit's `Stamp`
  for the state (staðfest, drög, óvíst, "?", lokið, fellur niður), the same patrol initial chip,
  the title, and the same exception wording: "19:30 Fært frá mið.", "Birnir fellur niður ·
  vetrarfrí", "+15 mín.".
- A multi-day event is the calendar's stamped strip (its `.strip` CSS, with punched ends) inside
  a grid row. Where it runs into the next week's row, the second segment starts "↳ … framhald"
  with a flat cut and is drawn but not announced twice, as in the calendar.
- Above the grid are the kit's `RhythmLegend` ("Fundir vikunnar: R Refir mán 17:30 · …") and the
  calendar's `StampKey`. The column headers lose their time slot, so a routine fundur shows no
  time, exactly as in the calendar.
- I put the rhythm **above the grid**, not in each column header. It's the same line, word for
  word, as in the calendar, so the eye learns it once. The header already carries the flokkur's
  colour and name.
- Past weeks are quiet and the dark-mode inks match, both from the calendar's CSS. The kit's
  thunk plays only when a stamp first appears or turns staðfest, and never under reduced motion.
- The week's note from the calendar ("Vetrarfrí í skólum 22.–26. okt.") sits under the week
  label.

**Information hierarchy:**

- Each week is a row. A week with troop-wide events gets an **"Öll sveitin" line** above the
  flokkar, spanning every column: skipulagsfundur, sveitarfundur, dagsferð, and the strips of a
  mót or útilega.
- Under it, one cell per flokkur, holding everything that flokkur has that week. That's often
  one quiet routine line; sometimes a cancelled fundur plus an aukafundur.
- **Side columns:** Búnaður shows an inked "ALLT TIL" stamp, tilted with the kit's
  `rotationFor`, or a dotted "3 vantar" slot. The Endurmat notes use the calendar's own patrol
  chip.

**Why it looks this way:** the calendar's look was picked and polished, so the grid shouldn't
invent a second language. The one real difference is structural. The calendar's columns are
days, while the grid's are flokkar, so troop events can't sit in a flokkur's column. They get
their own line in the week instead of today's "a band takes the whole week", which would hide
every flokksfundur that week.

**Trade-offs:**

- A week with many troop events becomes tall (week 5 has a mót, foreldrakynning, a
  skipulagsfundur and an útilega).
- Within a week a strip can't show _which_ days it covers by position, only by its date range.
  The calendar shows that by position.
- It's tied to the calendar's files (`components/plan/calendar/`). That's intended (one language), but a change there
  changes this.
- It runs on the calendar's fixture, not this lab's, so it isn't in the "Fundur element states"
  sheet. The calendar's own Stamp states and Key stories cover it.

**API it needs:** the same as the calendar's D4: `ends_at` and `cancelled`, plus the búnaður
(sc-644) and endurmat (sc-645) shapes above for the side columns. A troop line needs nothing
new: it's every band in the week.

### A1 · Staða

**The story it tells:** "This one's staðfest, that one's still drög, and those over there are
óvíst."

- **Information hierarchy:** the state as a glyph and a word in capitals (✓ STAÐFEST, ✎ DRÖG,
  ⧗ ÓVÍST, ? ÓÁKVEÐIÐ), then the title, then the exception flag, then the flokkur's initial,
  "3/4 liðir" and the minutes (red when over).
- **Why it looks this way:** it's the Dagatal's picked Staða look, so the two views speak the
  same language. The tile is tinted by state. "?" is dashed, past weeks go neutral and say
  "Lokið", and an exception gets a heavier left edge.
- **Side columns:** the "3 vantar" badge becomes a small status tile with ✕, matching the
  fundur tiles.
- **Trade-offs:**
  - Colour carries the state, and the flokkur moves to a small initial. You lose the flokkur's
    colour at a glance, though the column header still has it.
  - A busy future month is a lot of tinted tiles.
- **API it needs:** `decided_count`, `cancelled` and `ends_at`. Without `decided_count` it falls
  back to the status alone.

### A2 · Merki

**The story it tells:** "This term is a sash of badges, and this is how many we've sewn on."

- **Information hierarchy:** a round patch in the flokkur's colour with the fundur type's icon
  (a flag for a flokksfundur, people for a sveitarfundur, a tent, a mountain). Then the title,
  then the state in a word, then the exception.
- **Why it looks this way:**
  - **Staðfest** is a sewn patch: filled, with a stitched edge.
  - **Drög** and **óvíst** are an outline in the flokkur's colour.
  - **"?"** is an empty dashed ring.
  - **Cancelled** is a grey patch with a red stroke through it.
  - An **útilega or dagsferð** becomes a shield.
  - A **joint** event's patch is split between the two flokkar's colours.
  - **Past** patches turn grey, like a finished badge.

  There's no card around the element; the cell is the card.

- **Side columns:** the vantar count is a little round patch.
- **Trade-offs:**
  - The fullest fit with scouting, and the quietest grid of the four.
  - Drög and óvíst share the outline, so only the word tells them apart.
  - Patches need room: below about 9rem per column the title wraps to three lines.
- **API it needs:** only `cancelled` and `ends_at`. It reads the status and type the grid
  already has.

### A3 · Varðeldur

**The story it tells:** "How far along is each fundur? The fire tells you."

- **Information hierarchy:**
  - A fire to the left of the title. It's kindling while no liður is decided, then a small
    flame, a fire, and a big fire on a glow once all of them are.
  - A tally of the liðir (filled marks for the decided ones), then the minutes, red when over.
  - Past fundir show a grey, spent fire.
- **Why it looks this way:** status says what the leader _declared_; the fire shows how much
  work is actually done. The tally keeps the fire honest, since four sizes of flame aren't a
  number. A 3px edge in the flokkur's colour keeps the column readable.
- **Side columns:** the búnaður header becomes the same kind of tally, one mark per item (filled
  = eigum, tinted = vantar, dashed = óvíst), with "5/9 til" and the vantar badge.
- **Trade-offs:**
  - It needs `decided_count`, which the grid doesn't have, so without it this look can't exist.
  - Fire size is hard to compare across a row, so the tally does the real work.
  - The calendar lab is trying a growing campfire too, so pick one place for it.
- **API it needs:** `decided_count` (required), `cancelled` and `ends_at`.

### A4 · Stimpill

**The story it tells:** "Each fundur gets its stamp once it's ready. The empty boxes are your
to-do list."

- **Information hierarchy:**
  - **Ready** (staðfest, with every liður decided): a stamp with a double rule in the flokkur's
    colour, slightly crooked, saying ✓ KLÁRT, with the title under it.
  - **Not ready:** a dotted empty box with the title and "2 liðir eftir" (or "Óákveðið").
  - **Past:** a grey ✓ LOKIÐ stamp.
  - **Cancelled:** a red FELLUR NIÐUR stamp with a ban icon.
- **Why it looks this way:** it's binary on purpose, ready or not, like a scout passport. The
  grid splits into two textures you can tell apart from across the room: stamped and empty.
- **Side columns:** the búnaður header is an ALLT TIL stamp once everything is owned. Otherwise
  it's a dotted slot ("3 vantar", or "2/3 til").
- **Trade-offs:**
  - Drög and óvíst look the same, both empty with a count of what's left.
  - The past is the loudest part of the grid, since every past week is stamped. That's
    satisfying, but it pulls the eye backwards.
  - The tilt is decorative, and some will find it fussy.
- **API it needs:** `decided_count` (to know "every liður decided"), `cancelled` and `ends_at`.

## Checklist close-up

A's Búnaður list on its own (the A1 header):

- Ticking means **eigum**; unticked means **vantar**. **Óvíst** is the checkbox's mixed state,
  and once an item is ticked it can't go back to óvíst. That's A's main limit. A three-way
  control (as in the removed C/D) would fix it, at the cost of space.
- Vantar sorts first when the list opens. The list doesn't re-sort while you tick, so an item
  never jumps out from under your finger.
- What the sveit already had folds behind "Sýna 5 hluti sem við eigum".
- Every change is announced (`role="status"`: "Vasaljós ×6: eigum").
- Each checkbox is described by the liðir that need the item ("Fyrir: Ratleikur í Öskjuhlíð").

## Phone

The current grid squeezes four flokkar into about 40px each at 390px and clips the side columns
off. The lab gives the table a minimum width, scrolls it sideways and pins the week column. The
side columns are then a scroll away to the right, and busy weeks make tall rows. That's the cost
of keeping A's two columns. A phone-only fold (Endurmat and Búnaður as a line under each week)
is the obvious next step if A1–A4 settle.

## Copy and formats

- Counts go through `countIs`: "1 endurmat / 3 endurmöt", "1 liður / 2 liðir",
  "Eldsneyti · 2 brúsar", "Sýna 1 hlut / 5 hluti sem við eigum". The badge's spoken form is in
  the accusative: "Vantar 1 hlut / 3 hluti".
- Dates use `formatIcelandicDateShort`. Weekdays ("þri.", "fös.") are a local table, because
  `lib/format.ts` has no weekday helper yet; it should get one.
- Icons come from lucide-react: `Check`, `Pencil`, `Hourglass`, `Ban`, `CalendarClock`, `Flag`,
  `Users`, `Tent`, `Mountain`, `Flame`, `FlameKindling`, `MessageSquareText`, `Backpack`,
  `ThumbsUp`, `Wrench` and `X`.
