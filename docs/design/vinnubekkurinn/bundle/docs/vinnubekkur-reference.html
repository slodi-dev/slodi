Reglan sem allir íhlutir erfa

Dráttur er flýtileið, aldrei eina leiðin. Að bæta við, fjarlægja, endurraða og færa milli reita verður hvert um sig að vera framkvæmanlegt með lyklaborði og með sýnilegum hnappi á skjánum. Tvö viðmót, ein ástandsbreyting. Sé hönnun lögð fram þar sem aðgerð næst aðeins með mús er hún ekki fullnægjandi.

Þetta er ódýrt af því að bæði lögin senda sama áform í AssemblyProvider (sc-161). Ein kóðaleið, ein tilkynning, ein vistun — aðgengið getur ekki rekið hljóðlega frá bendihegðuninni.

type AssemblyIntent = | { t: 'insert'; block: BlockTemplate; slotId: string; at: number } | { t: 'move'; blockId: string; toSlotId: string; toIndex: number } | { t: 'remove'; blockId: string } | { t: 'duplicate'; blockId: string } | { t: 'setStatus'; blockId: string; status: BlockInstance['status'] };

Reitategundir og litir — engir nýir litir

setning drekar dagskrá primary leikur rekkar slit secondary endurmat fálkar sérsniðið border-strong

Reitategundirnar úr ADR-002 leggjast ofan á rampana sem kerfið á fyrir. Vinnubekkurinn bætir engum lit við kerfið. Litur ber aldrei merkingu einn — WCAG 1.4.1: heiti reitsins stendur alltaf skrifað við hliðina.

Staðfest Drög Í skoðun ? Óákveðið

„?“ er staða, ekki villa. ADR-002 §3 gerir óákveðið fyrsta flokks: foringi má skilja reit eftir opinn og halda áfram. Þess vegna hlutlaus litur og brotin lína — ekki rauður.

Aðgengisgátlisti — samþykktarskilyrði

  • Hverja blokk má bæta við, endurraða, færa og fjarlægja með lyklaborði einu saman.
  • Hver blokk hefur sýnilega ▲ ▼ hnappa og ⋯ valmynd (snerti- og lyklaborðsleið).
  • Rétt listamerking (role="list" / listitem); tilkynningar dnd-kit, aldrei aria-grabbed.
  • Fókus varðveitist í gegnum færslu — hann fylgir blokkinni á nýja staðinn.
  • Grip · færsla · sleppt · hætt við gefa hvert um sig aria-live tilkynningu.
  • Dráttarhaldið er raunverulegur fókusanlegur stýrihlutur með aria-label sem nefnir blokkina.
  • Auðir og skyldureitir komast til skila án sjónar (heiti + aria-describedby), ekki með brotinni línu einni.
  • Birtuskil og smellflötur um sl-* tákn; 44px flötur undir pointer: coarse.
  • prefers-reduced-motion virt í hverri dráttarhreyfingu.
  • Virkar í 200% aðdrætti og í einnar-dálks símaútliti.

Opnar spurningar — það sem hönnunarrýnin á að útkljá

  1. Ástandssafn. React context + useReducer fyrir fyrsta áfanga, eða Zustand strax? Forskriftin gerir ráð fyrir context/reducer.

  2. Færslur milli reita. Takmarkar reitategund hvað má sleppa í hana? Kortin sýna ógilt-sleppt stöðu — svarið breytir SlotFrame og DragOverlay.

  3. Afrit-með-götum. AssemblyHeader leggur til þriggja kosta glugga (beinagrind með götum / allt / allt með endurmötum). Staðfesta.

  4. Bakendagöt. is_template, order_index, staða og tímasetning eru ADR-002 byggingaratriði sem íhlutirnir gera ráð fyrir. Raða framenda á eftir þeim færslum.

  5. Innfelling. Þarf AssemblyCanvas að teiknast inni í töflu/tímalínu (A4, sc-39) strax í v1, eða má hann standa einn fyrst?

Röðun byggingar

  1. AssemblyProvider + áform + kyrrstæður AssemblyCanvas — ▲▼ + ✕ + „Bæta við“ í auðum reit. Fullnýtanlegt með lyklaborði, enginn dráttur.

  2. BlockPalette + BlockLibraryItem, innsetning með hnappi.

  3. dnd-kit lagt ofan á (bendi- og lyklaborðsskynjari) og notar sömu áformin.

  4. BlockInspector — staða, tímasetning, þemabreyta.

  5. AssemblyHeader „Afrita sniðmát“ → lokar B4-lykkjunni.

Skref 1–2 skila þegar nothæfum, aðgengilegum vinnubekk. Dráttur í skrefi 3 er hrein hröðun ofan á ástand sem er þegar sannreynt. Ný keyrsluháð eining: @dnd-kit/core + /sortable + /accessibility — staðfesta áður en hún er sett inn.
