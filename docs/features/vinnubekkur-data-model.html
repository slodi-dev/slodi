Vinnubekkurinn: the data model it needs

A proposal: the smallest set of tables and fields that would let Season, the Rist, the Dagatal, the Bekkur and the bank rail run on real data. It starts from the backend on origin/main. A liður is a Task: Content is already a Program, an Event or a Task, and a Program holds Events and Tasks while an Event holds Tasks. So the bench needs new fields on Task rather than a new table. This is the follow-up to vinnubekkur-backend-gaps.html.

Sources: frontend/services/plan.service.ts and components/plan/bench/benchState.ts on feature/sc-426-vinnubekkur-storybook; docs/frontend/plan-api-contract.md on release/vinnubekkur-v1; backend/app/models/* and repositories/moderation.py on origin/main. The bench intents then map onto existing routes: add and duplicate go to POST /events/{id}/tasks; patch, duration and moveToFundur to PATCH /tasks/{id}; remove to DELETE /tasks/{id}. Tagging goes through the existing PUT and DELETE /content/{id}/tags/{tag_id}. Moving a liður (move) changes the start times of the liðir after it, so it either becomes several PATCH calls or one new route that shifts them in one transaction. The band and lane intents (splitBand, mergeBand, lane*) go away once the bench becomes a single column, and so does status.

4. Rules the model has to enforce

  1. Planned tasks stay out of Yfirferð. The bank lists only the bank workspace's content, so a sveit's tasks never appear there. But the Yfirferð queue (ModerationRepository._apply_filters) reads Content from every workspace. Without a workspace filter, every liður a leader adds would land in front of Dagskrárstjórnarteymið. The queue needs Content.workspace_id = bank workspace, and that change has to ship before or with the bench.
  2. A liður dies with its fundur. Task.event_id is ON DELETE SET NULL today, so deleting a fundur would leave its liðir as loose tasks. Deleting an event in a season should soft-delete its tasks too.
  3. A task has one parent. It has event_id, program_id, or neither (a bank block), never both. A task in an event belongs to the event's program through the event.
  4. start_time only on a task in a fundur. A bank block has none, and copying a block into a fundur sets it.
  5. Start times fall inside the fundur. A liður starts no earlier than the event's start_dt, and the bench warns rather than refuses when one runs past end_dt. Gaps between liðir are allowed: a break is just time with nothing in it.
  6. Overlap only for different flokkar. Two liðir may run at the same time when each has a different patrol participant; that is how „each flokkur does its own verkefni“ works without lanes. Overlap otherwise gets a warning.
  7. Tags describe, they don't order. The bench draws liðir in start_time order and colours them by tag. It doesn't force Setning first or Slit last, and a liður with no tag is valid.
  8. The schema holds the three levels. Troop.division_id can only point at a division and Patrol.troop_id only at a troop, so the database itself refuses a flokkur under a deild. The service still checks that a parent is in the same workspace.
  9. Every workspace has exactly one default division, created with the workspace. The UI never shows it. A new sveit goes under it unless the félag has made deildir of its own.
  10. A sveit has at least one flokkur. Creating a sveit creates one flokkur with the sveit's name, so a small sveit is a sveit with a single flokkur. Deleting a sveit's last flokkur is refused.
  11. Scope is read, not stored. If a troop or division takes part, the event is troop_wide and fills the whole row. If a single patrol takes part, it's per_patrol and becomes a cell in that column. A per-patrol event has exactly one patrol participant.
  12. Participation narrows down the tree. A Task's participants must be at its Event, and an Event's at its Program, either directly or through their sveit or deild. With no rows of its own, Content is for whoever its parent is for.
  13. A unit colour is a validated hex. #rrggbb only, checked on write. A unit with no colour uses its parent's: a flokkur falls back to its sveit, a sveit to its deild. If none has one, the frontend picks by column position, as it does today. The bench has to keep text on it readable in both themes, so it picks white or dark text from the colour's lightness rather than trusting the colour to contrast.
  14. A unit belongs to one parent. Moving a flokkur to another sveit makes a new unit, so its history stays where it happened. This also avoids the troop bug where workspace_id can be changed without checking the target.
  15. A troop-wide event and a per-patrol cell can't share a week, unless the team confirms they can, in which case the grid needs an overflow affordance.
  16. copied_from_id is a copy, not a link. Editing the task never changes the bank block, and hiding or deleting the block never empties a fundur (ON DELETE SET NULL).
  17. A new starfsár inherits the schedule. Creating a season copies the meeting weekday, times and interval from the workspace's latest season, so nobody types „þriðjudagar 18:00–19:30“ every autumn. A season with no dates leaves them null.
  18. The frontend contract drops kind, status and type. plan-api-contract.md and plan.service.ts still have Season.kind, status: PlanStatus on grid entries and liðir, and type: EventType on grid entries. The frontend should tell a krassblað by its missing dates and read an event's type from its tags. The status chips and the „?“ marker in PlanEntryChip, LidurRow and LidurEditor go away. Patrol.accent (a name mapped to the --sl-color-patrol-* ramps) becomes color, a hex string, and a sveit can carry one too. PlanWeek.note is never sent, so the Rist's ATH column stays empty; it is optional in the contract, so nothing breaks.
  19. Endurmat stays in the sveit. A sveit's endurmat is a comment on its own task, so only its members can read it. Showing it on the bank block it came from, or to other sveitir, would be a separate decision to publish it.
  20. Who can edit: workspace editor or above for Season, Event and Task, the same as programs. Creating, renaming and deleting units needs workspace admin, which would also fix the viewer-can-create bug on troops.

5. Still to decide

  • What are today's troops rows? The migration assumes they are sveitir. If some were entered as flokkar, they have to become patrol units under a sveit instead. Check production before writing it.
  • Whose starfsár is a season? Season.unit_id can point at a sveit (its flokkar are the Rist's columns) or at a deild, including the hidden default one (every sveit's flokkar). The default deild is what makes a workspace-wide heildardagskrá possible without a nullable column.
  • Season on Event, or only through Program? A direct Event.season_id keeps the grid query to one join, at the cost of two paths that could disagree.
  • Where theme lives. It's on both Event and Task. Moving it up to Content would put it on Program too, and on every bank block.
  • The Færnimerki folder could also be tags, one per merki, instead of a new badge entity. That works if a merki needs nothing beyond its name.
  • Who may change Setning, Verkefni and Slit? Tags are global, and today any platform member can rename or delete any tag. Deleting „Setning“ would untag it on every fundur in every sveit. That may be acceptable, or tag editing may need to move to admins.
  • Should theme be a tag too? It's free text on Event and Task today, but if themes repeat (Útilíf, Hreyfing…), tags would make them filterable for free.
  • Saving: one PUT per fundur (the whole sheet) or one call per intent. Per fundur fits autosave (A3); per intent works better when co-leaders edit at once.

6. Parked

  • A group owning a workspace. Workspace.group_id and the groups table stay as they are on origin/main, but this model doesn't build on them. Later this can become a GroupUser that owns a workspace. Until then the bank rail has no Félagið folder, only the workspace's own content and the bank.
