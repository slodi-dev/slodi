Open: several people in one workspace

  • v1: the last change wins. The page reloads the opened structure every so often and when the window gets focus.
  • Later: a version on Placement and Content. A PATCH sends the version it saw and gets 409 if someone changed it in between; the frontend says „someone changed this, reload“.

Build order

Backend

  1. The migration: level, copied_from_id, placements, units, unit_participation; events' dates and parent pointers become placements; troops become units; the subtype tables and the workspace meeting fields go.
  2. Content routes as one (level on create, the level filter) and Yfirferð reading only the bank.
  3. Placements: list, open, create, move, delete.
  4. Units.
  5. Copies: copy with preview, copy weekly, own version.

Frontend

  1. Rewrite plan.service.ts against plan-api.html; drop Season, the grid endpoint, status, bands and lanes.
  2. The bank rail reads GET /workspaces/{id}/content. It can do this today.
  3. Build each view from one opened placement.
  4. Bench actions call the API instead of only the reducer.
  5. Wire onSelectEvent in the Rist.
